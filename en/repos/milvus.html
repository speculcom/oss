Milvus

milvus-io / milvus

A distributed vector database for large-scale retrieval, supporting HNSW, IVF, DiskANN, scalar filtering and multi-tenancy.

46.7k stars 4342 forks Go Language Apache-2.0 License Last push 2026-11-20

Why choose it

  • Designed for large collections and distributed deployment.
  • Several index types for different memory and latency budgets.
  • Scalar filtering and multi-tenancy are supported.

Not for

You have a few thousand vectors and want a local file.
You cannot operate a distributed cluster.

Minimum setup

  1. Start a single-node deployment and load 100k vectors.
  2. Compare HNSW and IVF on recall and latency.
  3. Test a filtered query and a tenant boundary.

Dependencies and cost

Check runtime, model weights and external service dependencies in the README.

License and usage boundaries

Code is Apache-2.0; model weights, training data and generated content may have separate terms — check each before commercial use.

Open source is not automatically commercial-use friendly: GPL / AGPL are copyleft; code, model and output licenses are separate. Read the LICENSE and model card before launch, and involve legal when needed.

Alternatives and neighbors

  • Qdrant — Production，A Rust vector database with filtering, hybrid search, distributed deployment and quantisation.
  • Weaviate — Production，A vector database with hybrid search: vectors plus BM25, multi-tenancy, modular vectorisation and reranking, with GraphQL and REST APIs.

Next steps

  • Open GitHub and read the README, LICENSE, latest release and issues first.
  • Make an onboarding checklist for deployment dependencies, VRAM, data, network and permissions.
  • Run a small sample first, then decide on production; never start with production data.
